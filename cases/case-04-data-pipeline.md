# 案例 04：多平台数据聚合与相关性打分管道

> 交付物类型：数据采集管道 + 打分模型 + 触达工具链
> 关键技术：多源适配 · 相关性打分调优 · 结构化提取 · 错误响应识别
> 状态：已完成，运行数据已验证

---

## 需求背景

需求方要从多个技术社区聚合"可能有商业价值的需求型帖子"，并且要求：

1. 自动判断哪些帖子值得跟进，不要人工翻
2. 提取发帖人联系方式（如果正文里有）
3. 新线索要及时提醒，不能错过时效
4. 生成可直接使用的沟通文案

**这类需求的常见做法是"抓下来 + 关键词匹配"，但实际效果很差**——因为关键词匹配的误报率极高，最后还是要人工再过一遍，等于没省时间。

本项目的核心工作量，其实在**打分模型的调优**上。

---

## 技术难点

### 难点 1：短英文关键词会污染匹配结果

第一版打分模型直接做子串匹配，结果排第一的是「招海外内容增长运营」：

```
命中: go, hook, 脚本
```

原因：`go` 这个关键词匹配到了 `golang`、也匹配到了 `content`、`digital` 里的字母组合；
`hook` 匹配到了包含该字母组合的普通单词。短文关键词在长文本里到处都是。

**解法**：按关键词类型区分匹配策略。

```
含非 ASCII 字符 → 直接子串匹配（中文没有词边界问题）
纯 ASCII 且长度 ≤ 4 → 词边界匹配  (?<![a-z0-9])kw(?![a-z0-9])
纯 ASCII 且长度 > 4 → 直接子串匹配
```

改完后误报基本消失。

### 难点 2：不同内容类型混在一起

采集到的内容混杂了多种类型，但它们**语义完全不同**：

| 类型 | 例子 | 是否线索 |
|---|---|---|
| 需求方发单 | "求人做 X，有偿" | ★ 是 |
| 全职招聘 | "招 X 工程师，20-30K，五险一金" | ✗ 不是（不是外包） |
| **同行发广告** | "[接单] 十年经验，可做 X" | ✗ 不是（是竞争者） |
| 技术讨论 | "感觉 X 的设计有问题" | ✗ 不是 |
| 开源分享 | "[开源] 我做了个 X 工具" | ✗ 不是 |

如果不区分，**同行广告会占据榜单前列**——因为它们大量使用行业关键词，分数天然很高。

**解法**：三个独立的分类器并行判断。

```python
# 分类器 1：供需方向
def detect_side(title, body):
    # 供给方特征（同行广告）：标题以 [接单][承接] 开头、含"可接单""已开源"
    # 需求方特征：含"求""找""有偿""报价""留联系方式"
    → "supply" / "demand" / "unknown"

# 分类器 2：雇佣形式
def detect_type(title, body):
    # 全职特征：五险一金、双休、年终奖、N-K 薪资范围、岗位职责
    → "fulltime" / "outsource" / "other"
```

**权重设计**（都是实测调出来的）：

```
同行广告     −60    ← 避免占用队列
全职招聘     −50    ← 不是外包单
需求方项目单 +25    ← 唯一加分项
```

**注意坑**：这个 +25 加分**必须绑定在"需求方"条件下**。第一版没加这个约束，导致无关内容（只要提到"兼职"两字）被抬到榜首。

### 难点 3：页面能抓到内容，但内容是错的

某个来源可以正常抓到页面，返回 333 个字符。看起来成功了，但内容全是导航文本：

```
首页 · 注册 · 登录 · 广告 · 板块名 · 子板块 ...
```

**误判风险**：以为抓取成功，实际上正文是空的，打分和提取全部建立在垃圾数据上。

**解法**：**站点 API 优先于页面抓取**。

```
优先级 1：站点公开 API       → 结构化数据最干净
优先级 2：站点专用 HTML 适配器 → 针对页面结构定制的提取规则
优先级 3：通用正文提取        → 兜底
```

关键设计：**不按"抓到多少字"判断成功，而按"数据来源可靠性"排序**。

### 难点 4：噪音过滤要防两类错误

直接从文本提取"需求要点"时，会抓到页面 UI 元素：

```
用example_user · 8 天前 · 1741 次点击     ← 被当成需求要点
```

这种错误**会直接毁掉沟通效果**——把这种东西写进话术里，对方一眼看出是机器生成的。

**解法**：20+ 条噪声特征过滤 + 回复区切分。

```
噪声特征（部分）：
  \d+\s*天前 / \d+\s*次点击 / \d+\s*回复
  纯符号行 / 纯数字行 / 用户名 · 时间戳组合
  中文少于 4 字且不含数字 → 丢弃
```

同时按标记（"全部回复""评论列表"）切掉回复区，避免评论区污染正文。

## 技术方案

### 架构

```
┌─ 采集层 ────────────────────────────────────┐
│ 源 1..N 适配器                               │
│  · 站点 API（优先）                          │
│  · 站点 HTML 适配器                          │
│  · 通用正文提取（兜底）                       │
│  · 域名镜像替换（不可达域名自动换源）          │
│  · RSS / 粘贴导入 / 任意 URL 解析             │
└───────────────────┬─────────────────────────┘
                    ↓ 归一化记录
┌─ 打分层 ────────────────────────────────────┐
│ 技术栈分（关键词，分隔符感知匹配）             │
│ 需求信号分（有偿/报价/包月…）                  │
│ 负向惩罚（白嫖/免费/毕设…）                    │
│ 类型修正（同行广告 −60 / 全职 −50 / 需方 +25）│
└───────────────────┬─────────────────────────┘
                    ↓ 分数 + 命中依据
┌─ 提取层 ────────────────────────────────────┐
│ 联系方式（明文 + Base64 打码，格式校验）       │
│ 结构化要点（噪声过滤 + 回复区切分）            │
│ 预算范围识别                                 │
└───────────────────┬─────────────────────────┘
                    ↓
┌─ 输出层 ────────────────────────────────────┐
│ 去重落库（内容指纹）                          │
│ 状态跟踪（待联系/已联系/已回复/成交/失败）      │
│ 实时推送到手机（webhook）                     │
│ 生成定制沟通文案                              │
└─────────────────────────────────────────────┘
```

### 打分模型

三段式结构，每段职责单一：

```
总分 = 技术栈分 + 需求信号分 − 负向惩罚 + 类型修正
```

**实测分数分布**（77 条真实数据）：

```
  100~999  :   2  ##
   50~ 99  :   7  #######
   30~ 49  :   5  #####
    0~ 29  :  11  ###########
  负分      :  52  ########################################

实际阈值设 30 分 → 14 条入队，52 条被负分过滤
```

**这个分布说明模型在起作用**：67% 的内容被正确识别为不相关（全职招聘、同行广告、技术讨论），没有污染结果。

### 关键设计决策

| 决策 | 理由 |
|---|---|
| 站点 API 优先于页面抓取 | 能抓到 ≠ 抓对了。本项目踩过"333 字全是导航" |
| 分类型关键词匹配 | 短英文词在长文本里到处误命中 |
| 供需方向独立分类器 | 同行广告的关键词密度天然很高，不单独处理会霸榜 |
| 类型加分绑定前提条件 | 加分不能无条件给，否则无关内容会被抬起来 |
| 打分依据随结果一起输出 | 便于人工复核和持续调优，而不是黑盒 |
| 内容指纹去重 | 同一内容多源出现只入库一次 |
| 状态字段跟踪全流程 | 避免重复联系同一个人 |

## 遇到的问题与解法

| 问题 | 现象 | 根因 | 解法 |
|---|---|---|---|
| **短英文词误命中** | "招运营"排到第一 | `go`/`hook` 在长文本里到处匹配 | 按关键词类型分别用子串/词边界匹配 |
| **同行广告霸榜** | `[接单] 十年经验…` 得 100 分 | 同行帖的行业关键词密度天然高 | 供需方向分类器 + 权重 −60 |
| **全职招聘混入** | 某招聘帖得 104 分排第二 | 招聘帖含大量技术关键词 | 雇佣形式分类器 + 权重 −50 |
| 加分绑错对象 | 无关内容被抬到榜首 | 类型加分未绑定前提条件 | 加分只在"需求方"时生效 |
| 页面抓到导航垃圾 | 正文全是"首页/注册/登录" | 该站是客户端渲染 | 站点 API 优先级提到最高 |
| **抓到 UI 当需求要点** | 把"xx · 8天前 · 1741次点击"写进话术 | 无噪声过滤 | 20+ 噪声特征 + 回复区切分 |
| 错误响应被当数据 | 把 `forbidden` 当业务数据 | 错误响应里也有数据字段 | 三重校验（错误码 + 特征字段 + 语义） |
| 短链展开失败 | HEAD 请求返回错误 | 该站对 HEAD 不友好 | 改 GET 逐跳跟随 |
